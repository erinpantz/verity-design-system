# Verity

Verity is Erin Tozour’s personal design system. It powers her portfolio site, and this Storybook is its documentation.

## Where things come from

- **Design:** the [Verity Library in Figma](https://www.figma.com/design/3Da0PcmwQjC19SKRduBuQD/Verity-Design-System) is the source of truth for design. The rules this code follows are in the **Guidelines** section of this Storybook: Naming, Spacing and rhythm, and Writing style.
- **Code:** components are built in React and TypeScript, styled with CSS Modules and design tokens. The source is on [GitHub](https://github.com/erinpantz/verity-design-system).

## How it’s organized

Components are grouped the same way as the Figma pages:

- **Actions:** buttons and other controls
- **Navigation:** moving between pages and sections
- **Layout:** containers, stacks, and grids
- **Text:** headings, body text, and prose
- **Media:** images, logos, and icons
- **Feedback and status:** placeholders while things load, the page loader, and labels that show a status
- **Content blocks:** larger sections built from the pieces above

## Principles

- **Every value comes from a token.** Colors, sizes, spacing, radii, and fonts are never hard-coded.
- **Components don’t add space outside themselves.** Parents space their children.
- **Accessibility is built in.** Every interactive component has default, hover, focus, active, and disabled states, and each story is checked in the Accessibility panel.

## Links and routing

Every Verity link is a real `<a href>`: it works before JavaScript runs, and it can be copied, shared, and opened in a new tab. On its own, following one reloads the whole page. A site with a router, like React Router, wraps itself in `LinkProvider`, and Verity renders links to the site’s own pages with the router’s link instead, so the page changes in the app, faster, and the site sees the change coming (Shell’s `pending`, and `PageLoader`).

**Which links go through it:** only pages on the same site, an address that starts with one `/` (not `//`), with no `target`, no `download`, and no file extension at the end of its path. Everything else stays a plain `<a>`: other sites, `mailto:` links, anything that opens in a new tab, and files like the resume PDF, which a router would try to show as a page. Without a LinkProvider, every link is a plain `<a>`.

With React Router, the site adapts its `Link` in a few lines, passing `href` on as `to`:

```tsx
import { Link as RouterLink } from 'react-router';
import { LinkProvider, type LinkComponent } from 'verity-design-system';

const SiteLink: LinkComponent = ({ href = '', ...props }) => <RouterLink to={href} {...props} />;

<LinkProvider component={SiteLink}>
  <App />
</LinkProvider>
```

The router’s link renders the `<a href>` and keeps its own features, like prefetching on hover, and it leaves a Cmd-click or middle click to the browser, so it still opens a new tab. See **Actions › LinkProvider** to try it.
