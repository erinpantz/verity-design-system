# Button

Starts an action, like booking a call or downloading a résumé. Use primary for the main action in a group and secondary for the others.

<Canvas of={ButtonStories.Default} />

## When to use

- **For an action, or a call to action that goes to another page,** like opening a booking form, downloading a file, or “Book a call.”
- **Primary for the main action,** and only one per group, so it’s clear what to do first.
- **Secondary for the other actions** next to it, or on their own when the action is less important.
- **Not with only an icon.** Use `IconButton`, which shows its label in a tooltip.

## Accessibility

With `href`, it’s a link that goes through `LinkProvider`, so with a site’s router, a link to one of the site’s pages changes the page in the app (see **Actions › LinkProvider**).

A Button renders a `<button>` with `type="button"` by default, so it never submits a form by accident. It works with the keyboard (Tab, then Enter or Space), and its label is its name for screen readers. Icons are decorative and hidden from screen readers.

| Situation | What to do | Example |
|---|---|---|
| Writing the label | Start with a verb that says what happens. Keep it short, since it stays on one line. | “Book a call,” not “Click here” |
| It sends a form | Use `type="submit"`. | “Send message” |
| It goes to another page | Use `href`. It renders a link (`<a>`) that looks like a button, so screen readers say “link” and people can open it in a new tab. | “Book a call” to Calendly |
| It downloads a file | Add `download`, with `href` to the file. The browser saves it instead of opening it, which matters most in a web app on a phone’s Home Screen, where an opened PDF has no way back. `download` alone keeps the file’s name; `download="Erin-Tozour-resume.pdf"` names the saved file. Start the label with “Download” and use the `download` icon, so people know what happens. It stays a plain `<a>`, never a router’s link. Not with `opensInNewTab`: that’s a type error. | “Download” |
| It goes to another site people come back from | Add `opensInNewTab`. It opens the page in a new tab with `rel="noopener noreferrer"`, so that page can’t control this one, and screen readers hear “opens in a new tab” after the label. Use it only for pages on other sites, like a booking page. | “Book a meeting” to Calendly |
| It can’t be used yet | Use `disabled`. Keyboard users skip disabled buttons, so say on the page why it’s disabled. | “Send message” before the form is filled in |
| It isn’t ready yet, and a hint says why | Use `disabled` with `tooltip`. It stays in the tab order (`aria-disabled` instead of `disabled`), so keyboard users can reach it and see the hint, and screen readers hear the label, then the hint. Pressing it does nothing. Like a disabled `Link` with a tooltip. | “Check it out,” with “Coming soon” |
| It sits on a colored band | Use the `color` that matches the background. | `color="brand"` on a brand-colored band |

## Variant and color

Each variant has its own colors for each background. `color` is typed with `variant`, so only these pairs are allowed:

| `variant` | `color` | Background | Tokens | Focus ring |
|---|---|---|---|---|
| `primary` | `default` | The site’s background | `--verity-button-primary-color-*` | `--verity-color-border-focus` |
| `primary` | `brand` | A brand-colored band | `--verity-button-primary-brand-color-*` | `--verity-color-border-focus-brand` |
| `secondary` | `default` | The site’s background | `--verity-button-secondary-color-*` | `--verity-color-border-focus` |
| `secondary` | `knockout` | A light band | `--verity-button-secondary-knockout-color-*` | `--verity-color-border-focus-knockout` |

Primary is filled. Secondary is outlined with a `--verity-border-width-md` border and no fill.

The focus ring sits on the background, not on the button. When a band chooses Button colors that don’t match its background, it sets the ring to its background’s focus color, so the ring keeps a 3:1 contrast ratio. Hero does this: on its knockout background, the primary default button gets `--verity-color-border-focus-knockout`.

## Background

For a button that floats over pictures or scrolling content, like the action in Shell’s focused mode, `background="scrim"` puts a dark see-through fill under it, so its label stays readable over whatever’s behind. It’s BackLink’s look, and the same prop and values as IconButton’s.

| `background` | What’s behind the label | Tokens |
|---|---|---|
| `none` | The default: nothing, as above | — |
| `scrim` | The scrim, and no visible border. Secondary default only: `background` is typed with `variant` and `color`, so scrim on any other pair is a type error, and it’s ignored if it gets through. | `--verity-color-background-scrim` |

On a scrim, the label and icon match BackLink’s: `--verity-color-content-default` in every state except disabled, which keeps secondary’s disabled color. At `md`, the icon is `--verity-icon-size-sm` (20), like BackLink’s; other sizes keep Button’s own icon size. Size, padding, gap, corners, and label style are Button’s own; at `md` they match BackLink.

| State | On a scrim | Tokens |
|---|---|---|
| Default | The scrim, with no shadow, and the label and icon in the default content color | `--verity-color-background-scrim`, `--verity-color-content-default` |
| Hover and focus | The lift with `shadow-md` (see Motion). The label stays `--verity-color-content-default`. No hover fill, like BackLink: on a brand-colored page, a fill over the scrim comes out almost the page’s color. Focus adds the focus ring. | `--verity-shadow-md-*`, `--verity-color-content-default` |
| Active | A stronger fill on top of the scrim, settled back down | `--verity-color-background-transparent-strong` |
| Disabled | The scrim, with the disabled label | `--verity-button-secondary-color-content-disabled` |

## Size

Height and side padding come from the control tokens, so buttons line up with other controls of the same size. On Medium and Small screens, sm and md stay at least 44 tall, so they’re easy to tap.

| `size` | Height | Side padding | Label | Icon | Use for |
|---|---|---|---|---|---|
| `xl` | `--verity-control-size-xl` (56–64) | `--verity-control-padding-x-xl` (24) | label-lg | `--verity-icon-size-lg` | The one call to action on a page |
| `lg` | `--verity-control-size-lg` (48–56) | `--verity-control-padding-x-lg` (24) | label-lg | `--verity-icon-size-lg` | Calls to action in a section |
| `md` | `--verity-control-size-md` (40–44) | `--verity-control-padding-x-md` (16) | label-default | `--verity-icon-size-md` | The default: most buttons |
| `sm` | `--verity-control-size-sm` (32–44) | `--verity-control-padding-x-sm` (12) | label-sm | `--verity-icon-size-sm` | Tight spaces, like a card’s footer |

The space between an icon and the label is `--verity-control-gap` (8). The label stays on one line, and a button keeps its size in a full row instead of shrinking.

## States

| State | Primary | Secondary | Tokens |
|---|---|---|---|
| Default | Filled | Outlined | `…-default` |
| Hover | A lighter fill and label, and the lift (see Motion) | A lighter border and label, and the lift | `…-hover` |
| Focus | A focus ring outside the button, following its corners, and the lift. Keyboard focus only. | The same | `--verity-focus-ring-width`, `--verity-focus-ring-offset`, and the focus color for its `color` |
| Active | The active fill and label while pressed. It settles back down, with no growth or shadow, so pressing reads as pushing it in. | The active border and label, settled | `…-active` |
| Disabled | The disabled fill and label, and no lift | The disabled border and label, and no lift | `…-disabled` |

## Motion

On hover and keyboard focus, a button rises, grows a little, and casts a shadow, like the cards, so every button on the site answers the pointer the same way. Button, IconButton, and BackLink share one rule for it (`Button/lift.module.css`), so they can’t drift apart. Each keeps its own colors.

| What | How | Tokens |
|---|---|---|
| The lift | Up by `--verity-motion-lift-sm` (4) on hover and focus, and back down on mouse out, blur, or press. Not `lift-md`: 8 is a fifth of a 40px button’s height. | `--verity-motion-duration-playful`, `--verity-motion-easing-standard` |
| The growth | To `--verity-motion-scale-hover` (2%) with the lift. It shows most on wide buttons. | The same |
| The shadow | `shadow-md` on hover and focus only, never at rest, fading in. Not `shadow-lg`, which is sized for the cards. | `--verity-shadow-md-*`, `--verity-motion-duration-fast`, `--verity-motion-easing-standard` |
| The colors | Switch at once, as before | — |
| Reduce motion is on | No lift or growth; the shadow still fades in, since it doesn’t move anything | — |

- **Hover only with a real pointer** (`hover: hover`), so a tap doesn’t leave a button raised. Keyboard focus lifts it on every device, and the focus ring moves and grows with it.
- **The hit area stays put.** While a button is raised, an invisible layer covers the space it rose from, so a pointer at its bottom edge stays over it, and the hover doesn’t flicker on and off.
- **Not on the `as="span"` look**: the link or card around it already lifts.

## Inside a link or button

A link or button can’t hold another one. When something that’s already a link needs a button’s look, like the label on a `PortfolioCard`, use `as="span"`. It renders a plain `<span>` with the button’s look and no focus, role, or click of its own, so the link around it stays the one thing to press. `type`, `disabled`, `onClick`, `href`, `opensInNewTab`, and `download` don’t apply.

It follows the link or button around it: its hover look while that’s hovered (devices with a real pointer) or has keyboard focus, and its active look while it’s pressed. It never shows a focus ring and never lifts on its own: the parent has the ring, and a card around it lifts.
