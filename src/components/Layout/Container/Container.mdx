# Container

Centers a page’s content in one column, so every block shares the same left and right edges. Images, galleries, and grids can break out to the full width.

<Canvas of={ContainerStories.Default} />

## When to use

- **Around each block of page content,** so its edges line up with the blocks above and below it.
- **For content without a heading,** like the case study header or a wide image between Sections. With a heading, use a `Section`, which works the same way.
- **Not for the space between blocks.** A Container adds no space above or below itself; the layout around it owns that space.
- **One thing inside.** A Container adds no gap, so two things placed straight in it touch. For more than one, put a `VerticalStack`, `HorizontalStack`, `Grid`, or `Section` in its content and let that set the space. For images seen together as one set, use a `Gallery`. See **Guidelines › Spacing and rhythm**.

## Accessibility

A Container renders a `<div>` by default. Use `as` to choose the element, based on what the Container holds.

| Situation | What to do | Example |
|---|---|---|
| It introduces the page | Use `as="header"`, for one Container per page. | The page title and intro at the top of a case study |
| It introduces a topic with a heading | Use a `Section` instead. It renders a `<section>` named by its heading, with the same column. | A “Process” heading and the content under it |
| It has no heading | Leave `as` out, so it renders a `<div>`. | A wide image between sections |

## Width

Every block sits in the content column, `--verity-content-column-width` (880), centered. So text, MediaText, quotes, and lists all share left and right edges down the page, and lines of text stay a readable length.

A `MediaBlock`, `Gallery`, `Grid`, `VerticalStack`, or `HorizontalStack` can break out with `width="wide"`, up to `--verity-content-wide-width` (1824), still centered. Nothing else does, except two blocks that are always wide: the `Footer`, as the page’s closing band, and `CaseStudyHighlights`. So a wide block always reads as intentional.

| Block | Width | Token |
|---|---|---|
| Everything, by default | The column | `--verity-content-column-width` (880) |
| `MediaBlock`, `Gallery`, `Grid`, `VerticalStack`, or `HorizontalStack` with `width="wide"` | The full width | `--verity-content-wide-width` (1824) |

The width applies to the outermost block. An `Image` inside a `MediaBlock` takes the MediaBlock’s width; a MediaBlock inside a `Gallery` or a stack takes the Gallery’s or the stack’s. In Figma, set those inner MediaBlocks to `Width=wide`, since each MediaBlock holds itself to the column there.

**When to go wide:** sparingly, to highlight something or show detail. Most images read best in the column: they line up with the text, take less space, and let the reader see more of the story at once.

The page’s side margins come from Shell, so a Container has none of its own.

**Why one column:** blocks of different widths left uneven right edges, especially where MediaText met Prose. One column keeps every edge aligned, and centering it shares the leftover space on large screens between both sides, which looks more balanced than leaving it all on the right.

## In Figma

| Figma | Code |
|---|---|
| Component `Container` | `<Container />` |
| Slot `Content`, holding one item | `children` |
| The element named in the description: header, section, or div | `as` |
