# Shell

The page frame, in one column: the site’s nav across the top, then the page column with Main and the Footer, and the theme toggle in the screen’s bottom-right corner. Every page of the site uses it. In focused mode, for reading one piece of work, a link back replaces the nav.

<Canvas of={ShellStories.Large} />

## When to use

- **Once per page, around everything,** with the page’s content as Main and the site’s `Footer`.
- **In focused mode for a case study,** with `mode="focused"` and a `backLink` to the page it came from. See **Mode**.
- **Not inside another layout.** It sets the whole page, from the skip link to the footer.

## Accessibility

| Part | What it renders | What it does |
|---|---|---|
| Skip link | “Skip to content,” a primary `Button` link | First in the tab order. It’s off screen until it has keyboard focus, then shows at the top start corner. It moves focus to Main, so the next Tab goes to the first link in the page’s content (WCAG 2.4.1). |
| Nav | `MainNav`’s `<nav>` | The navigation landmark. Not in focused mode. |
| Back link | `BackLink`, an `<a href>` | Focused mode only, in place of the nav. In the tab order: the back link, then the theme toggle, then Main. |
| Theme toggle | `ThemeToggle`, a `<button>` | Right after the nav and before Main in the tab order, so it’s reached early on every page without being part of the navigation |
| Main | `<main>` | The main landmark, with the page’s content. It can take focus from the skip link (`tabIndex={-1}`), but it isn’t in the tab order. After a page change, focus goes to its `h1` (see below). |
| Footer | The `Footer`’s `<footer>` | The footer landmark (`contentinfo`) |
| Menu | `NavOverlay`, inside MainNav | The links, as a dialog, when the nav is too narrow for them. MainNav opens it; Shell sets nothing up. Not in focused mode. |

The skip link works the same in both modes: it moves focus to Main.

### After a page change

When the site changes the page in the app, without a reload, the browser leaves focus where it was: on the link that was followed, or nowhere. So the site moves it to the new page with `focusPageStart()`, from Verity:

- **It focuses the page’s heading,** the first `h1` in Main, so a screen reader announces the new page by name. VoiceOver reads “Portfolio, heading level 1,” not “main.” The heading isn’t a control, so it gets `tabindex="-1"` (reachable by code, not by Tab) and no focus ring.
- **With no `h1`, it focuses Main,** where the skip link sends focus.
- **It doesn’t scroll.** The site’s router decides that: the top for a new page, where you were for Back and Forward.
- **The next Tab** goes to the first link or button after the heading.

Call it after every page change except the first load, in the site’s root:

```tsx
import { focusPageStart } from 'verity-design-system';

useEffect(() => {
  if (key !== firstKey.current) focusPageStart();
}, [key]);
```

`NavOverlay` calls it too, when it closes because one of its links was followed. While the menu is open, the page behind it can’t take focus, so the site’s call can come too early to work; and as a modal dialog closes, the browser sends focus back to the menu button. So whichever runs last, focus ends on the new page’s heading.

## Width

Shell is one column at every width: MainNav, then Main, then the Footer. The nav stays at the top of the screen as the page scrolls (see Nav, below). Shell has no breakpoints of its own: MainNav picks its layout from its own width.

| Screen | Nav |
|---|---|
| XL, Large, and Medium from 624 | The full logo and the links |
| Medium under 624, and Small from 488 | “Erin” and the links |
| Small under 488 | The full logo and the menu button, which opens the links in NavOverlay |

See **Navigation › MainNav** for how it decides.

The page is one layer, over Shell’s background. Moving media that a default `Hero` puts behind the page, like a Reel’s cards, passes behind Main, the Footer, ThemeToggle, and BackLink, and stays in sight above the background. The page column clips sideways only, so a card swinging past the window’s edge never makes the page scroll sideways, and cards can still rise toward the nav, passing under it (see **Content blocks › Hero**, Media).

## Nav

In default mode, the nav stays at the top of the screen as the page scrolls, at every width and in every layout. **Why:** on a long page, people scroll past the nav and forget it’s there, and the way to the other pages disappears with it. The nav is short, so keeping it costs little room. Case studies, in focused mode, have no nav, and don’t change.

| What | How |
|---|---|
| Sticking | `position: sticky` at the top, in CSS, so it sticks before JavaScript runs. It keeps its size: it only stops moving. |
| Background | `--verity-color-background-default`, solid, so the page passes cleanly underneath |
| Divider | Once the page has scrolled away from the top, a line along its bottom edge: `--verity-color-border-divider` at `--verity-border-width-sm`, drawn inside the nav, so its size doesn’t change. It fades in and out over `--verity-motion-duration-fast`, and appears at once with reduce motion on. At the top of the page, the nav looks exactly as it does in place. |
| How Shell knows you’ve scrolled | A 1px marker at the very top of the page. When it leaves the screen, the page is scrolled (an `IntersectionObserver`). Without JavaScript, the nav still sticks, without the divider. |
| Layer | Above the page’s content, including moving media behind the page (a Reel’s cards in a default Hero) and a `LayeredImage`’s shapes, which pass under it. Above PageLoader, so it stays visible and usable while a page loads. Below the skip link. NavOverlay opens over everything, from the stuck nav too. |
| Nothing hides under it | Shell measures the nav’s height, which changes with its layout and the breakpoint, and sets the page’s `scroll-padding-top` to it. A link to a heading, the skip link’s target, and anything that gets keyboard focus land below the nav, not under it (WCAG 2.4.11, Focus Not Obscured). |

## Mode

`mode` is a real choice between two ways to read the site, not a preview.

| `mode` | What it shows | Use for |
|---|---|---|
| `default` | The site’s nav, MainNav, across the top | Pages people move between: the portfolio, the playground, the profile |
| `focused` | No nav. A `BackLink` floats in the top-left corner, and ThemeToggle stays in the bottom-right. | One piece of work read from start to end, like a case study |

**Why focused mode:** a case study is long, and people read it start to end. With the nav gone, the page gets the whole width at every breakpoint and nothing beside it competes with the work. The way out stays in one place: the back link, always in reach in the corner, names the page it goes back to.

In focused mode:

| What | How |
|---|---|
| The back link’s position | Fixed to the top-left corner: `--verity-spacing-md` from the top and `--verity-main-padding-inline` from the left, the page’s own side margin, so it lines up with the page’s content. Plus the safe area (`env(safe-area-inset-top)` and `env(safe-area-inset-left)`). |
| Where it goes | `backLink`: its `href` and `label`. It’s `{ href: '/', label: 'Portfolio' }` unless you set it. |
| The space above Main | `--verity-main-padding-top-focused` (72) plus `--verity-spacing-lg`, as in Figma: the first clears the back link (its inset plus its height), and the second is the usual space above the first section. So the title starts 120 down on XL and Large, `--verity-spacing-lg` below the link. A link that jumps to a heading stops at the same place. |
| Layer | Like the theme toggle: above the page’s content, which scrolls under it |

## Page loader

Shell places `PageLoader` right below the nav (at the top, in focused mode), and drives it from two props. Once the page has scrolled, the loader starts at the stuck nav’s bottom edge.

| Prop | What it does |
|---|---|
| `pending` | The section a page change is going to, while it’s going: `home`, `portfolio`, `profile`, or `playground` (a case study is `portfolio`). Set it when someone follows a link to another section, and set it back to undefined when the new page is ready. PageLoader decides whether to show. |
| `loaderWords` | Each section’s loading words, plain lines like “Shuffling the deck.” PageLoader adds the ellipsis and shuffles them. |

- **The nav link swaps poses** while the change is going or the loader shows, whichever is longer, in step with the loader. Home’s link is the logo, which doesn’t move.
- **The page Shell is on counts as visited:** `current`, a case study (focused mode) as Portfolio, and anything else as Home.
- **What stays above the loader:** the nav, ThemeToggle, BackLink, and the skip link, so they stay usable while a page loads. NavOverlay is in the browser’s top layer.
- **When nothing is pending,** the nav is exactly as it is without a loader.

See **Feedback and status › PageLoader** for when it shows, its motion, and its words.

## Theme toggle

Shell renders `ThemeToggle` and fixes it to the screen’s bottom-right corner, at every width. In the corner it’s in the same place on every screen, it’s always in reach while the page scrolls, and the nav holds only places to go.

| What | How |
|---|---|
| Position | `--verity-spacing-md` (24–32) from the bottom and right edges, plus the safe area (`env(safe-area-inset-bottom)` and `env(safe-area-inset-right)`) for a phone’s rounded corners and home bar |
| Layer | Above the page’s content, which scrolls under it. Below anything modal: `NavOverlay` is a modal dialog, in the browser’s top layer, so it covers the toggle while the menu is open. |
| Surface | A scrim, so it stays readable over whatever scrolls under it (see **Actions › ThemeToggle**) |

At the end of a page, it sits at the Footer’s bottom-right corner, in the copyright’s row, below the cards, so it never covers one, at every breakpoint.

## Space

| Space | Token |
|---|---|
| Above the first section in Main | `--verity-main-padding-top` (56–72), the same as the space between sections. In focused mode, `--verity-main-padding-top-focused` plus `--verity-spacing-lg` instead. |
| Between sections in Main, and between Main and the Footer | `--verity-main-spacing-section-gap` |
| Below the Footer | `--verity-spacing-lg` |
| The page’s sides, around Main and the Footer | `--verity-main-padding-inline` (24–80) |
| The theme toggle, from the screen’s bottom and right edges | `--verity-spacing-md`, plus the safe area |
| The back link, from the screen’s top and left edges (focused mode) | `--verity-spacing-md` and `--verity-main-padding-inline`, plus the safe area |

Shell owns the page’s side margins, so nothing inside Main needs its own. Containers and Sections center their content in the same column inside them, and the Footer spans the wide width, up to `--verity-content-wide-width`.
