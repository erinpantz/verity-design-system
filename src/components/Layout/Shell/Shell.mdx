# Shell

The page frame: the site’s nav, the theme toggle in the screen’s bottom-right corner, and the page column with Main and the Footer. Every page of the site uses it. In focused mode, for reading one piece of work, a link back replaces the nav.

<Canvas of={ShellStories.Large} />

## When to use

- **Once per page, around everything,** with the page’s content as Main and the site’s `Footer`.
- **In focused mode for a case study,** with `mode="focused"` and a `backLink` to the page it came from. See **Mode**.
- **Not inside another layout.** It sets the whole page, from the skip link to the footer.

## Accessibility

| Part | What it renders | What it does |
|---|---|---|
| Skip link | “Skip to content,” a primary `Button` link | First in the tab order. It’s off screen until it has keyboard focus, then shows at the top start corner. It moves focus to Main, so the next Tab goes to the first link in the page’s content (WCAG 2.4.1). |
| Nav | `MainNav`’s `<nav>` | The navigation landmark. Not in focused mode. |
| Back link | `BackLink`, an `<a href>` | Focused mode only, in place of the nav. In the tab order: the back link, then the theme toggle, then Main. |
| Theme toggle | `ThemeToggle`, a `<button>` | Right after the nav and before Main in the tab order, so it’s reached early on every page without being part of the navigation |
| Main | `<main>` | The main landmark, with the page’s content. It can take focus from the skip link (`tabIndex={-1}`), but it isn’t in the tab order. |
| Footer | The `Footer`’s `<footer>` | The footer landmark (`contentinfo`) |
| Menu | `NavOverlay` | The full menu on Small and Medium, as a dialog. Not in focused mode. |

The skip link works the same in both modes: it moves focus to Main.

On Small, the top bar is pinned, so whatever a link jumps to, like Main from the skip link or a heading in the page, stops just below it (`scroll-padding-top` from `--verity-nav-container-thickness-collapsed`).

## Width

How Shell is laid out follows the screen width, in CSS with the generated breakpoints, so it’s right before JavaScript runs. What the menu button does is MainNav’s.

| Width | Nav | Page column |
|---|---|---|
| XL and Large | On the left, full height, staying put. Expanded when the page opens; the menu button collapses it to the rail. | Beside the nav, scrolling |
| Medium | The rail, on the left, full height, staying put. The menu button opens the full menu. | Beside the rail, scrolling |
| Small | The top bar, pinned while the page scrolls. The menu button opens the full menu. | Below the bar, scrolling |

The nav always opens expanded on XL and Large, and doesn’t remember the toggle between visits.

## Mode

`mode` is a real choice between two ways to read the site, not a preview.

| `mode` | What it shows | Use for |
|---|---|---|
| `default` | The site’s nav: MainNav docked on the left, or the top bar on Small, with NavOverlay for the full menu | Pages people move between: the portfolio, the playground, the profile |
| `focused` | No nav. A `BackLink` floats in the top-left corner, and ThemeToggle stays in the bottom-right. | One piece of work read from start to end, like a case study |

**Why focused mode:** a case study is long, and people read it start to end. With the nav gone, the page gets the whole width at every breakpoint and nothing beside it competes with the work. The way out stays in one place: the back link, always in reach in the corner, names the page it goes back to.

In focused mode:

| What | How |
|---|---|
| The back link’s position | Fixed to the top-left corner: `--verity-spacing-md` from the top and `--verity-main-padding-inline` from the left, the page’s own side margin, so it lines up with the page’s content. Plus the safe area (`env(safe-area-inset-top)` and `env(safe-area-inset-left)`). |
| Where it goes | `backLink`: its `href` and `label`. It’s `{ href: '/', label: 'Portfolio' }` unless you set it. |
| The space above Main | `--verity-main-padding-top-focused` (72) plus Main’s own `--verity-spacing-lg`, as in Figma: the first clears the back link (its inset plus its height), and the second is the usual space above the first section. So the title starts 120 down on XL and Large, `--verity-spacing-lg` below the link. A link that jumps to a heading stops at the same place. |
| Layer | Like the theme toggle: above the page’s content, which scrolls under it |

## Theme toggle

Shell renders `ThemeToggle` and fixes it to the screen’s bottom-right corner, at every width. It used to sit in the nav, at the bottom of the rail and at the end of the Small top bar. In the corner it’s in the same place on every screen, it’s always in reach while the page scrolls, and the nav holds only places to go.

| What | How |
|---|---|
| Position | `--verity-spacing-md` (24–32) from the bottom and right edges, plus the safe area (`env(safe-area-inset-bottom)` and `env(safe-area-inset-right)`) for a phone’s rounded corners and home bar |
| Layer | Above the page’s content, which scrolls under it. Below anything modal: `NavOverlay` is a modal dialog, in the browser’s top layer, so it covers the toggle while the menu is open. |
| Surface | A scrim, so it stays readable over whatever scrolls under it (see **Actions › ThemeToggle**) |

At the end of a page, it sits at the Footer’s bottom-right corner, over the Footer’s band but not over any of its links, at every breakpoint.

## Space

| Space | Token |
|---|---|
| Above the first section in Main | `--verity-spacing-lg`, plus `--verity-main-padding-top-focused` in focused mode |
| Between sections in Main, and between Main and the Footer | `--verity-main-spacing-section-gap` |
| Below the Footer | `--verity-spacing-lg` |
| The page’s sides, around Main and the Footer | `--verity-main-padding-inline` (24–48) |
| The theme toggle, from the screen’s bottom and right edges | `--verity-spacing-md`, plus the safe area |
| The back link, from the screen’s top and left edges (focused mode) | `--verity-spacing-md` and `--verity-main-padding-inline`, plus the safe area |

Shell owns the page’s side margins, so nothing inside Main needs its own. Containers and Sections center their content in the same column inside them, and the Footer spans the wide width, up to `--verity-content-wide-width`.
