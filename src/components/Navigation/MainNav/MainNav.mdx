# MainNav

The site’s main navigation, a bar across the top of the page: the logo, linking home, then a link to each page, Portfolio, Profile, and Playground. It scrolls away with the page, so the page’s content gets the screen. Where the links don’t fit, a menu button opens them in `NavOverlay`.

<Canvas of={MainNavStories.Full} />

## When to use

- **Once per page, at the top.** `Shell` places it; pass `current` and `hrefs` to Shell.
- **While a page change is going,** `pending` names the section it’s going to, and that page’s link swaps its icon between poses, in step with `PageLoader`. Home’s link is the logo, which doesn’t move, and in the menu layout, the menu button doesn’t either. Shell sets it for you. When nothing is pending, the nav is as always.
- **Not for links within a page or in the footer.** Use `Link`, or `LinkGroup` for a group of them. Resume isn’t in the nav: it’s in the site’s `Footer`.
- **Not pinned to the top.** It scrolls away with the page. Don’t wrap it in a sticky container.

## Accessibility

Its links, the logo and the NavItems, go through `LinkProvider`, so with a site’s router, they change the page in the app (see **Actions › LinkProvider**).

MainNav renders a `<nav aria-label="Main">`, so screen readers list it as the main navigation landmark. Inside it:

- **The site title** is a link home whose only content is the logo, so its name is the logo’s: “Erin Tozour.” It’s the same name whether the full logo or “erin” shows. The logo that isn’t showing is `display: none`, so screen readers skip it too and hear the name once.
- **The pages** are a list (`<ul>`) of three `NavItem` links, so screen readers say how many there are. The current page has `aria-current="page"`.
- **In the menu layout,** the links in the bar are `display: none`, hidden from screen readers as well as from sight, and the menu button shows. It’s an `IconButton` named “Open menu,” and tells screen readers that it opens a dialog (`aria-haspopup="dialog"`) and whether it’s open (`aria-expanded`). In the other layouts, the menu button is `display: none`.

## Layout

MainNav’s own width picks one of three layouts, not the screen’s width. It measures its content, inside its side padding, against two tokens:

| Content width | Layout | Logo | At the end |
|---|---|---|---|
| At least `--verity-main-nav-short-logo-width` | `full` | The full logo | The links |
| Under that, but at least `--verity-main-nav-menu-width` | `short` | “erin” (`ErinTozourLogo name="first"`) | The links |
| Under `--verity-main-nav-menu-width` | `menu` | The full logo | The menu button, which opens the links in `NavOverlay` |

### The two widths

Each is the space the layout above it needs, rounded up: the logo, `--verity-main-nav-gap`, and the three NavItems with the link gaps between them. They change with the breakpoint, because the logo, the gaps, and the NavItems do. If a nav label changes, recompute them in Figma.

| Token | XL and Large | Medium and Small | Made of |
|---|---|---|---|
| `--verity-main-nav-short-logo-width` | 620 | 544 | The full logo, the gap, and the links: 212 + 32 + 374, or 159 + 24 + 358 |
| `--verity-main-nav-menu-width` | 484 | 440 | “erin,” the gap, and the links: 75 + 32 + 374, or 56 + 24 + 358 |

### On screens

In Shell, the nav spans the screen, so its content is the screen’s width less the page’s side margins (`--verity-main-padding-inline`, twice). That puts the switches at these screen widths:

| Screen | Layout |
|---|---|
| XL and Large (960 and up) | Always `full` |
| Medium, 624 and up | `full` |
| Medium, 560 to 623 | `short` |
| Small, 488 to 559 | `short` |
| Small, under 488 | `menu` |

The width is measured on the nav, not the screen, so the nav picks the right layout wherever it’s placed, as in the stories above, where it sits in a narrower box.

### How it works in code

It’s all CSS, so the first paint is right before JavaScript runs. MainNav is a container (`container: main-nav / inline-size`), and `@container` rules switch the layout. A container query can’t read a CSS custom property, so `npm run tokens` writes the two widths for each breakpoint into `src/styles/container-widths.generated.module.css`, and each `@container` rule sits inside its breakpoint’s `@media` rule. The tokens stay the only source: change them in Figma, export, and run `npm run tokens`.

## Space

| Space | Token |
|---|---|
| Above the nav | `--verity-padding-md` |
| Below the nav | `--verity-padding-xs` |
| The sides, so the logo lines up with the page’s content | `--verity-main-padding-inline` |
| The least space between the site title and the links or menu button. The site title fills the rest of the row, so the links sit at the end. | `--verity-main-nav-gap` |
| Between the links | `--verity-main-nav-link-gap` |
| Under the logo, which lifts it so its lowercase letters line up with the link labels | `--verity-main-nav-logo-offset` |
| The logo’s height; its width follows | `--verity-main-nav-logo-height` |

The links and menu button are centered vertically against the site title.
