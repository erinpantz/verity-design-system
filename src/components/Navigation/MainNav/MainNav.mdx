# MainNav

The site’s main navigation: the menu button, the site title, a link to each page, Resume, and the theme toggle. In the side nav, a thin line sets Resume apart from the pages, because it opens a PDF rather than a page on the site, and ThemeToggle sits alone at the bottom. It changes with the screen width, from a top bar on phones to a side nav on wide screens.

<Canvas of={MainNavStories.Default} />

## When to use

- **Once per page, inside `NavContainer`,** which docks it to the side or the top.
- **Inside `NavOverlay`,** with `placement="overlay"`, for the full menu on Small and Medium.
- **Not for links within a page or in the footer.** Use `Link`, or `LinkGroup` for a group of them.

## Accessibility

MainNav renders a `<nav aria-label="Main">`, so screen readers list it as the main navigation landmark. Inside it:

- **The site title** is a link home whose only content is the logo, so its name is the logo’s: “Erin Tozour.”
- **The pages and Resume** are a list (`<ul>`) of four `NavItem` links, so screen readers say how many there are and read them in a row. The current page has `aria-current="page"`.
- **The line above Resume** is a CSS border. It only groups the links for the eye, so screen readers don’t announce it: it isn’t an `<hr>` or `role="separator"`.
- **ThemeToggle** is a button: it changes the page instead of going somewhere (see **Actions › ThemeToggle**). So it sits after the list, outside it but still in the nav, and comes last in the tab order, as it does on screen.
- **On Small,** a second ThemeToggle sits in the top bar. Only one of the two is ever shown, and the hidden one is hidden from screen readers too.
- **The menu button** is an `IconButton`. What it does, and what it tells screen readers, depends on the width:

| Width | The menu button | Screen readers hear |
|---|---|---|
| Large and XL | Collapses the nav to the rail, or expands it | “Collapse navigation, expanded,” or “Expand navigation, collapsed” (`aria-expanded`) |
| Small and Medium | Opens `NavOverlay` | “Open menu,” that it opens a dialog (`aria-haspopup="dialog"`), and whether it’s open (`aria-expanded`) |
| In NavOverlay | Closes the overlay | “Close menu” |

In the rail, each NavItem’s label is hidden from sight but stays in the link, so the link keeps its name. The label also shows in a tooltip, which screen readers skip.

## Width

How MainNav looks is all CSS, keyed to the generated breakpoints, so it’s right before JavaScript runs. What the menu button does comes from the `useBreakpoint` hook, with the same values.

| Width | Layout | Figma |
|---|---|---|
| Small (under 560px) | A top bar: the menu button, the logo, and ThemeToggle at the end. The pages are in NavOverlay. ThemeToggle’s tooltip opens below it, where it fits. | `State=collapsed, Dock=top` |
| Medium (560 to 959px) | The rail: the menu button, each page’s icon, then Resume, with ThemeToggle at the bottom. No logo. | `State=collapsed, Dock=left` |
| Large and XL (960px and up) | Expanded, as `state` starts it: the logo and menu button, each page with its label, then Resume, with ThemeToggle at the bottom. The menu button switches to the rail and back. | `State=expanded, Dock=left` and `State=collapsed, Dock=left` |

## Placement

| `placement` | What it does | Use for |
|---|---|---|
| `page` | The default. The layout follows the width, as above. | The nav in NavContainer |
| `overlay` | Always expanded, and the menu button closes the menu | The nav in NavOverlay |

| The logo’s height; its width follows | `--verity-main-nav-logo-height` |
