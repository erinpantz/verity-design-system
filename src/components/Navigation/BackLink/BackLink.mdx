# BackLink

A link back, with a back arrow, on a scrim: “Back.” A click returns to the previous page when the site handles it, and otherwise goes to the page above this one. In Shell’s focused mode, it floats in the top-left corner in place of the nav.

<Canvas of={BackLinkStories.Default} />

## When to use

- **In Shell’s focused mode,** where Shell places it for you: set `mode="focused"` and `backLink` on Shell. See **Layout › Shell**.
- **To go back,** like from a case study, the résumé, or a Playground project to wherever the visitor came from. Visitors reach these pages from more than one place, and expect Back to return there.
- **Not for links within a page or in running text.** Use `Link`.
- **Not for an action that changes the page.** Use `Button` or `IconButton`: a BackLink always goes somewhere.

## Accessibility

Its link goes through `LinkProvider`, so with a site’s router, going back to one of the site’s pages changes the page in the app (see **Actions › LinkProvider**).

A BackLink renders an `<a href>`, so it works like any link: Enter follows it, and screen readers announce it as a link. Its name is its `label`. The arrow is decorative and hidden from screen readers, since “link” already says it goes somewhere.

| Situation | What to do | Example |
|---|---|---|
| Writing the label | “Back.” It’s true wherever the link goes, and it’s short, so it fits beside an action on any phone. | “Back” |
| Choosing the href | The page above this one, like the portfolio. It’s where the link goes for visitors who arrived from outside the site, like a search or a shared link, before JavaScript loads, and when it’s opened in a new tab. | `href="/"` |
| Going back in the history | Pass `onClick`. When the previous page is on the site, the site calls `event.preventDefault()` and goes back; otherwise it does nothing, and the link follows `href`. Leave modified clicks (Cmd, Ctrl, Shift, the middle button) to the browser, so they still open `href` in a new tab. Verity has no router, so the site decides. | See below |

With React Router, check `window.history.state.idx`: React Router’s position in the history for this visit, `0` on the first page. Above `0`, the visitor came from a page on the site. Don’t check whether the location’s key is `"default"`: with React Router’s scroll restoration, the first page gets a key too. That’s React Router’s own field, so a site with another router uses that router’s equivalent.

```tsx
const navigate = useNavigate();

<BackLink
  href="/"
  label="Back"
  onClick={(event) => {
    const modified = event.metaKey || event.ctrlKey || event.shiftKey || event.altKey || event.button !== 0;
    // React Router's history position: 0 on the first page of a visit
    const cameFromSite = (window.history.state?.idx ?? 0) > 0;
    if (modified || !cameFromSite) return; // follow href
    event.preventDefault();
    navigate(-1);
  }}
/>
```

In Shell’s focused mode, pass the same `onClick` in `backLink`, and Shell passes it to the BackLink.

## States

The surface is always a scrim, so it stays readable over whatever scrolls under it. On hover and focus it lifts, grows a little, and casts a shadow, the lift every button shares (see **Actions › Button**), with no change of fill: on the brand-colored page, a hover fill over the scrim came out almost exactly the page’s color, so the surface disappeared. Press adds a stronger fill on top of the scrim. It has no shadow at rest: on a button this small, a blurred shadow there looks fuzzy.

| State | What changes | Tokens |
|---|---|---|
| Default | The scrim, and the arrow and label in the default content color | `--verity-color-background-scrim`, `--verity-color-content-default` |
| Hover | It lifts, grows, and takes `shadow-md`, with no change of fill: the scrim stays as it is. Devices with a real pointer only, so a tap doesn’t leave it raised. | `--verity-motion-lift-sm` (4), `--verity-motion-scale-hover`, `--verity-shadow-md-*` |
| Focus | The hover lift, plus the shared focus ring, which moves with it. Keyboard focus only, on every device. | `--verity-focus-ring-width`, `--verity-focus-ring-offset`, `--verity-color-border-focus` |
| Active | It settles back down, with no growth or shadow, so pressing reads as pushing it in, and a stronger fill over the scrim | `--verity-color-background-transparent-strong` |
| Disabled | None: a link back always goes somewhere | — |

## Motion

| What | How | Tokens |
|---|---|---|
| The lift and growth | Up by `--verity-motion-lift-sm` and to `--verity-motion-scale-hover` (2%) on hover and focus, and back down on mouse out, blur, or press. The same rule as Button and IconButton, in `Button/lift.module.css`. | `--verity-motion-duration-playful`, `--verity-motion-easing-standard` |
| The shadow | `shadow-md`, fading in on hover and focus, and out on press. None at rest. | `--verity-shadow-md-*`, `--verity-motion-duration-fast`, `--verity-motion-easing-standard` |
| The press fill | Switches at once, like IconButton’s | — |
| Reduce motion is on | No lift or growth. The shadow still fades in on hover and focus, focus shows its ring, and press its fill. | — |

**Only what you see moves.** The link is the hit area and stays still; the surface inside it (the scrim, the press fill, the shadow, and the focus ring) is what lifts. If the whole 40px link moved, a pointer near its bottom edge could end up below it as it rose, end the hover, drop it back, and make it flicker.

In Shell’s focused mode it stays clear of the screen’s top edge when lifted, and nothing clips it.

## Color

The label stays readable on the scrim even over a white picture: about 17:1 over the page’s background and over 8:1 over white, in both themes.
