# Writing style

## Principle

Write the way I talk: clear, specific, and human. Names match everywhere they appear, so the nav label, the page heading, and the URL always agree and people know where they are.

## Capitalization

Sentence case everywhere: capitalize the first word and proper names only. It’s easier to read, and there are no rules to remember about small words.

| What | Rule | Examples |
|---|---|---|
| Headings | Sentence case for page titles, section headings, and case study titles. | Saving admin time and improving care quality<br />What I learned |
| Buttons and links | Sentence case. Start with a verb that says what happens next. Link text says where it goes, never “click here”. | Book a call, View case study<br />Not: Book A Call, Click here |
| Nav items and page names | One or two words, usually nouns. The nav label, the page heading, and the URL match. | Portfolio → “Portfolio” → /portfolio<br />Playground, Profile, Resume |
| Small labels | Type labels and eyebrows in sentence case. The text style makes them uppercase, so screen readers and code get normal text. | Type “Pages”, it shows as PAGES |
| Tooltips | Sentence case, a few words, no period. | Coming soon |
| Proper names | Keep the capitalization the name uses itself. | Verity Design System, Laguna Companion, LinkedIn, Calendly, Figma |

## Voice

This is my site, so it speaks as me.

| What | Rule | Examples |
|---|---|---|
| Person | First person: I, me, my. Use “we” only for work done with a team, and say who the team was. | I led the research.<br />We (a team of four) shipped it in six weeks. |
| Contractions | Use contractions whenever they sound natural. They keep the writing conversational and human. Skip ones people rarely say out loud. | don’t, I’m, it’s, I’ve, that’s<br />Not: do not, I am, mightn’t, I’d’ve |

## Punctuation

| What | Rule | Examples |
|---|---|---|
| Periods | Only at the end of full sentences in body text, descriptions, and captions. Never in headings, buttons, links, labels, nav items, or tooltips. | Book a call<br />Have a project in mind? Book a 30-minute call. |
| Serial comma | Use a comma before “and” or “or” in a list of three or more. | research, design, and testing |
| And, not & | Write “and”. Use “&” only when it’s part of a proper name or space is very tight. | Saving admin time and improving care quality |
| Quotes and apostrophes | Use curly quotes and apostrophes. | I’m, “design”<br />Not: I'm, "design" |
| Ranges | Use an en dash with no spaces for ranges of numbers and dates. | 2019–2023, 3–5 weeks |

## Applying the rules

When a component has default text, write it to these rules too, so every new instance starts out right. When copy changes in a component or case study, check it against this page. Ask Claude to review the copy in the Figma file or a page of the site against these rules.
