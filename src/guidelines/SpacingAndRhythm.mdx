# Spacing and rhythm

## Principle

Components never add space outside themselves. The space between things belongs to whatever holds them: a stack’s gap, a Section, or Main in the Shell. That way a component looks right wherever it’s placed, and spacing changes in one place instead of on every instance. The one exception is prose, where each block of text sets the space above itself.

## Who owns the space

Each level of a page owns one kind of space. When something looks too close or too far apart, change it at the level that owns it.

| Level | Owns | Set with |
|---|---|---|
| Main (in Shell) | The page’s side margins, and the space between Sections on a page. | Side padding of Main and the Footer → `main/padding-inline`<br />Main gap → `main/spacing/section-gap` |
| Section | The space between its heading and intro, between its header and content, and between the blocks in its Content slot. | Heading to intro → `spacing/sm`<br />Header to content → `spacing/md`<br />Between blocks → `spacing/xl` |
| Container | No space. It centers its content in the content column, with no side margins, and its content has no gap, so it holds one thing. | — |
| Stacks | The space between siblings when you compose a layout. | `VerticalStack` and `HorizontalStack` gap → `spacing/*` |
| Inside a component | The space between a component’s own parts, and the padding inside anything with a background, border, or tap area. | Auto layout gap and padding → `spacing/*`, `padding/*`, `control/*`, or a Tier 3 token |
| TextBlock | The space between a heading and the component it introduces, such as a list or a Grid of stat cards. | Heading to body → `spacing/sm` |
| Prose | The space above each block of long-form text. | `ProseItem` space before → `viewport/typography/*/space-before` |

## Rules

| What | Rule | Examples |
|---|---|---|
| No outside space | A component’s root has no space before, margin, or padding that pushes other things away. Root padding is only for a visible background, a border, or a tap area. | `Grid`, `TextBlock`, and `MediaBlock` have no space before. `Hero` has padding because it has a background. |
| Gaps, not spacers | Space between siblings comes from the parent’s gap. Don’t add empty frames or extra padding to push things apart. | `ProseItem`’s space before is the only spacer, because each type of text needs different space above it. |
| Every value is a token | Gaps, padding, and control sizes are bound to variables. Never type a number. | `Hero` Actions gap → `spacing/xs`, not 8. |
| Choose the right tier | Use Tier 2 tokens for general spacing. Use a Tier 3 token when the value belongs to one component. Never bind Core Tier 1 tokens directly. | `spacing/xl` between Section blocks. `nav-item/padding` inside `NavItem`. Not `spacing/8`. |
| Gap or padding | `spacing/*` is the space between things. `padding/*` is the inset inside a container. | Section blocks → `spacing/xl`. `Hero` inset → `padding/lg`. |
| Stack or frame | Use a stack when people compose the content, like a slot or a page layout. A fixed group inside a component can be an auto layout frame, as long as its gap is a token. | `VerticalStack` in a page layout. `Hero`’s Actions frame. |
| One column, with wide breakouts | Every block in a Section or Container sits in the content column (`content/column-width`, 880), centered, so all blocks share left and right edges. Only `MediaBlock`, `Gallery`, and `Grid` can break out, with Width `wide` (`content/wide-width`, 1824). | Prose, MediaText, and a TextBlock of stat cards all 880 wide; a screenshot below them at `width="wide"`. |
| One thing per Container | A Container adds no gap, so two things placed straight in it touch. For more than one, put a stack, a `Grid`, or a `Section` in it, and let that set the gap. | Two screenshots → a `VerticalStack` in a `Container`. |
| Same size, same height | Controls take their height from `control/size/*`, not from their content plus padding, so different controls line up side by side. | An `lg` `Button` next to an `lg` `TextInput`. |

## A heading and what it introduces

A heading sits close to what it introduces. Where the heading goes depends on what comes after it.

| After the heading | Put the heading | Space between them |
|---|---|---|
| Paragraphs, or a Markdown list | In `Prose`, as a heading block (`###` in Markdown) | The paragraph’s space before → `padding/sm` |
| A component, such as an `UnorderedList`, a `Grid` of `StatCard`s, or a `Gallery` | In a `TextBlock`, with the component in its body | `spacing/sm` |

**Why:** a Section puts `spacing/xl` between its blocks. A heading at the end of a Prose block is a separate block from the component after it, so it sits as far from what it labels as from the block above it, and reads as detached. In a `TextBlock`, the heading and its component are one block.

| Do | Don’t |
|---|---|
| “Outcomes” as a `TextBlock`, with a `Grid` of `StatCard`s in its body | `### Outcomes` at the end of a Prose block, with the `Grid` after it |
| “Takeaways” as a `TextBlock`, with an `UnorderedList` in its body | A Prose block that ends with a heading, in Figma or in Markdown |

In MDX, the `TextBlock` wraps the component: `<TextBlock heading="Takeaways">` before the `<UnorderedList>`, and `</TextBlock>` after it.

**Exception:** a component that illustrates the paragraphs above it, such as a `MediaBlock` or a pair of quotes after a paragraph, stays its own block in the Section. Its heading introduces the paragraphs, not the image, so it stays in Prose.

## More than one thing in a Container

A Container centers its content in the column. Its content has no gap, so it holds one thing. For more than one, put one of these in it and let it set the space:

| What’s in it | Use | Space between them |
|---|---|---|
| Things stacked top to bottom, such as full-width screenshots | `VerticalStack` | Its `gap` option (`md` by default) |
| Things side by side, such as buttons | `HorizontalStack` | Its `gap` option |
| Items of equal weight that wrap into rows, such as stat cards | `Grid` | Its `gap` option: `md` by default, `lg` for quotes |
| A set of images shown together | `Gallery` | Its own layout |
| A heading and the blocks under it | `Section` | `spacing/xl` between blocks |

**Why:** a gap on Container would make it a second kind of stack, with one spacing chosen for everything inside it. Keeping it to width means the space always comes from a component made to set it, which you can see and change in one place.

| Do | Don’t |
|---|---|
| Two screenshots in a `VerticalStack`, inside a `Container` | Two `MediaBlock`s straight in a `Container`’s Content slot |
| A `Gallery`, when the images are one set seen side by side | Two `Image`s next to each other in a `Container` |

## Spacing scale

Responsive Tier 2. Each token has a value for every breakpoint, so spacing tightens on smaller screens without changing the design. The values at each breakpoint are on **Foundations › Spacing and layout**, generated from the tokens.

| Token | Use for |
|---|---|
| `spacing/none` | Removing a gap on purpose |
| `spacing/xxs` | Tight groups: comma and title, label pairs |
| `spacing/xs` | Buttons side by side, small groups, list items |
| `spacing/sm` | Heading to body |
| `spacing/md` | Section header to content |
| `spacing/lg` | Separate blocks inside a component, like MediaText’s text and media |
| `spacing/xl` | Between blocks in a Section |
| `padding/xs` | Small containers |
| `padding/sm` | Cards |
| `padding/md` | Larger panels |
| `padding/lg` | `Hero` and other full-width bands |
| `main/spacing/section-gap` | Between Sections in Main |

## Prose rhythm

Inside Prose, each `ProseItem` adds space above itself based on its type: more before headings, less between paragraphs. Prose itself has no gap. The first item in a block has no space before: in Figma, turn off Space before on it; in code, the prose styles do this automatically.

| `ProseItem` type | Space before token |
|---|---|
| `heading-1` | `viewport/typography/heading-1/space-before` → `padding/lg` |
| `heading-2`, `heading-3` | `viewport/typography/heading-2…3/space-before` → `spacing/lg` |
| `body-lg`, `body-default`, `body-sm` | `viewport/typography/body-*/space-before` → `padding/sm` |
| `blockquote` | `viewport/typography/blockquote/space-before` → `spacing/lg` |

## Controls

Buttons, icon buttons, and inputs share one size scale, so controls of the same size are the same height side by side. The height is fixed by the token, and padding is only on the left and right. On Medium and Small, every size stays at 44 or more for touch. The values at each breakpoint are on **Foundations › Spacing and layout**.

| Token | Use for |
|---|---|
| `control/size/sm`, `md`, `lg`, `xl` | Height (and width for square controls) |
| `control/padding-x/sm`, `md`, `lg`, `xl` | Left and right padding |
| `control/gap` | Icon to label |

## Component tokens

When a value belongs to one component, it gets a Responsive Tier 3 token named after that component, so it can change per breakpoint later without touching the component.

| Group | Used for |
|---|---|
| `content/*` | The content column (`column-width`, 880) and the full width wide blocks can reach (`wide-width`, 1824), for `Container` and `Section`. |
| `grid/columns` | The column guides in Figma (`Container`, `Section`, and `Shell`). Not used by components in code. |
| `grid/item-min-width/*` | How narrow a `Grid` item can get before the row wraps (`sm` 200px, `md` 300px). |
| `main-nav/*` | Link gap, group gap, and site title inset in `MainNav`. |
| `nav-item/*` | `NavItem` padding (its tap area) and icon-to-label gap. |
| `nav-container/*`, `nav-overlay/*` | Navigation thickness and padding. |

The space between `Grid` items uses `spacing/md` by default, or `spacing/lg` for quotes (Grid’s `gap`). The gutters of the Figma column guides use `spacing/md`. `grid/gutter` was removed on October 28, 2026.

## In code

The same rules apply in code, written in CSS.

| Rule | In code |
|---|---|
| No outside space | No `margin` on a component’s root element. |
| Gaps, not spacers | The parent sets `gap` on a flex or grid layout. No spacer elements. |
| Every value is a token | Use `--verity-` custom properties, e.g. `gap: var(--verity-spacing-lg)`. Never type a pixel value. |
| Prose rhythm | Inside `Prose`, each block (a heading, paragraph, list, or blockquote) gets `margin-block-start` from its space-before token, and the first block has none. Docs pages get the same rhythm, because `VerityDocs` uses `Prose`. |

## Keeping spacing consistent

Ask Claude to audit spacing in the Figma file with the `figma-spacing-audit` skill. The audit lists gaps and padding without tokens, Core Tier 1 tokens used directly, plain frames that could be stacks, headings set as plain text, and any space outside a component. You review the list and approve the fixes.

The same skill audits page designs that use the library. It finds instances of components or variants that no longer exist, spacing overrides left over from older versions, Prose blocks that end with a heading followed by a component, and Containers that hold more than one thing.
